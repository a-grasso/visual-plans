## Objective

Deliver a single `EnrichmentRunner` that takes an account id, drives the
research → extract → detect → score pipeline, and persists one `AccountProfile`.
**Done** means: given a seeded account, one call yields a validated profile row
and a green end-to-end test.

This plan touches `server/enrichment/` and reuses the existing ports in
`server/llm/` — it adds the glue, not new model integrations.

<Callout tone="decision" title="Committed approach">

Runner is a **plain orchestrator**, not a framework. It sequences existing ports
and writes through the persistence layer. No new abstraction until a second
pipeline needs it.

</Callout>

## Approach

<Columns>
  <Column label="Current">
    Ports exist in isolation (`ResearchPort`, `ExtractionPort`) and are exercised
    only by opt-in live tests. Nothing wires them together.
  </Column>
  <Column label="Target">
    `EnrichmentRunner.run(accountId)` calls each port in order, maps outputs to
    `AccountProfile`, and persists it. Callers get one entry point.
  </Column>
</Columns>

### The runner itself

<AnnotatedCode
  file="server/enrichment/EnrichmentRunner.kt"
  lang="kotlin"
  code={`class EnrichmentRunner(
  private val research: ResearchPort,
  private val extraction: ExtractionPort,
  private val repo: ProfileRepository,
) {
  suspend fun run(accountId: String): AccountProfile {
    val dossier = research.gather(accountId)
    val topics = extraction.extract(dossier)
    val profile = ProfileMapper.toProfile(accountId, topics)
    return repo.upsert(profile)
  }
}`}

## Risks

<Callout tone="note" title="Assumption">

Research + extraction latency is acceptable for a synchronous endpoint at this
scale (< 30s). If not, the runner moves behind a job queue — out of scope here.

</Callout>
